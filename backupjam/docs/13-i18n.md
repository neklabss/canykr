# 13 — Internationalization Implementation

## Single source of truth

```
packages/i18n/locales/<tag>.json   ICU MessageFormat, flat dotted keys (e.g. "nav.discover")
packages/i18n/locales/_registry.json   tag, native name, direction, status, Flutter id
        │
        ├─► API (NestJS): localized errors + transactional emails
        ├─► Web (Next.js): server translator + client provider (only the active catalog is shipped)
        ├─► Admin: catalog fetched from GET /v1/i18n/messages/:locale
        └─► Mobile (Flutter): scripts/export-arb.mjs → apps/mobile/lib/l10n/app_<id>.arb → gen_l10n
```

**Adding a language:** add `<tag>.json` + one registry entry, then run `pnpm i18n:check` and `pnpm i18n:arb`. No application code changes (Flutter needs `flutter gen-l10n`, run automatically).

## Locale status — what "supported" means

| Status | Meaning |
|---|---|
| `reviewed` | Complete and reviewed by a native speaker (currently: `en`) |
| `machine_draft` | 100 % key coverage, valid ICU, correct plural categories — **awaiting native review**. Shown in pickers, but must not be marketed as officially supported (docs/20) |

The 16 launch locales (`en tr es pt-BR fr de it ar ru uk hi id ja ko zh-Hans zh-Hant`) are complete; 15 are `machine_draft`.

## Negotiation (identical rules on every surface)

`manual preference (account / cookie / device setting) → ordered device or browser languages → English`

- Exact tag → Chinese script inference (`zh-TW/HK/MO → zh-Hant`, other `zh → zh-Hans`) → language+region → language+script → language only.
- `pt-PT → pt-BR` (best available), `es-419 → es`, unknown (`sw`) → next preference → `en`.
- Implementations: `packages/i18n/src/negotiation.ts` (TS) and `apps/mobile/lib/core/locale_resolution.dart` (Dart); both covered by the same test cases.

## Language ≠ country ≠ currency

`user_preferences.locale` (UI language, `NULL` = automatic), `country_code` (market rules, nearby content), `currency_code` (display only), `time_zone`. Example in e2e tests: a Turkish-speaking user in Germany gets a Turkish UI, German market and EUR display. Converted prices are labelled approximate (`price.convertedNotice`); offers settle in their original currency (docs/15).

## Formatting

| Need | API |
|---|---|
| Plurals / selects | ICU via `intl-messageformat` (TS) and `gen_l10n` (Dart). ICU `#` is rewritten to `{count}` for Flutter during ARB export |
| Money | `formatMoney(amountMinor: bigint, currency, locale)` — string decimal, no float; ISO exponent (JPY 0, KWD 3) |
| Dates | `formatDateTime(date, locale, timeZone)`; events store an IANA zone |
| Country / currency / language names | `Intl.DisplayNames` (no hand-translated lists) |
| Collation | `Intl.Collator(locale)` for sorted country lists |

## RTL & layout

- Web: `<html dir>` from the registry; CSS uses logical properties (`inset-inline-start`, `border-inline-start`, `margin-inline`).
- Flutter: `Directionality` from the resolved locale; Android `supportsRtl=true`.
- Layouts budget +40 % string length (docs/06); tests render German on 320–360 px widths with overflow assertions.

## User-generated content translation (planned, flag `i18n.ugc_ai_translation`)

Original text is always stored and displayed on request; machine translations are stored separately with `source_locale`, `engine`, `created_at`, rendered with `translation.aiDisclosure` + `translation.showOriginal`; requires the `ai_translation` consent for the author's content where legally necessary.
